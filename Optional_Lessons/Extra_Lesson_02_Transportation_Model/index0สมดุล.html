01 / Academic foundation

หลักการทางวิชาการ: ปัญหาการขนส่งกับการเลือกทำเลโรงงาน

วิเคราะห์ปัญหาด้วยการวิจัยดำเนินงาน (Operations Research) และการกำหนดการเชิงเส้น (Linear Programming)

THEORY

ปัญหาการขนส่ง (Transportation Problem) เป็นแบบจำลองการจัดสรรสินค้าจากแหล่งต้นทาง (Sources) หลายแห่งไปยังปลายทาง (Destinations) หลายแห่ง โดยกำหนดปริมาณการส่งผ่านแต่ละเส้นทางให้บรรลุความต้องการทั้งหมด ภายใต้ข้อจำกัดด้านกำลังผลิต และมีต้นทุนรวมน้อยที่สุด ปัญหานี้เป็นกรณีเฉพาะของ Linear Programming และเชื่อมโยงกับปัญหาการไหลในโครงข่ายที่มีต้นทุนต่ำสุด (Minimum-Cost Flow)

1 · Facility Location

ตัดสินใจว่าโรงงานใหม่จะตั้งที่ใด โดยเลือกเพียงหนึ่งทำเลจากตัวเลือกที่กำหนด

2 · Transportation Allocation

กำหนดว่าแต่ละโรงงานควรผลิตและจัดส่งสินค้าไปยังลูกค้ารายใด จำนวนเท่าใด

3 · System Cost Optimization

ลดต้นทุนรวมทั้งระบบ ไม่ใช่ลดเฉพาะค่าขนส่งหรือเลือกโรงงานที่ต้นทุนผลิตถูกที่สุด

Min Z = Σi Σj (Pi + Cij) Xijต้นทุนรวมต่ำสุด = ผลรวมของ [ต้นทุนผลิตต่อหน่วย + ต้นทุนขนส่งต่อหน่วย] × ปริมาณสินค้าที่ส่ง

ตัวแปรตัดสินใจ Xij

จำนวนสินค้าที่ส่งจากโรงงาน i ไปยังลูกค้า j (หน่วย/สัปดาห์) โปรแกรมจะค้นหาค่าของตัวแปรเหล่านี้ เพื่อให้ต้นทุนรวมต่ำที่สุด

เหตุใดต้องหาค่าเหมาะสมที่สุด?

เส้นทางที่ถูกที่สุดสำหรับลูกค้ารายหนึ่ง อาจแย่งกำลังผลิตจากเส้นทางที่จำเป็นกว่าสำหรับลูกค้าอีกราย จึงต้องพิจารณาการจัดสรรทุกเส้นทางพร้อมกัน

คำศัพท์วิชาการที่ควรรู้
Feasible Solution: แผนขนส่งที่ไม่ละเมิดข้อจำกัด
Optimal Solution: แผนที่เป็นไปได้และทำให้ต้นทุนรวมต่ำที่สุด
Balanced Transportation: ผลรวมกำลังผลิตเท่ากับความต้องการรวม
Unbalanced Transportation: ผลรวมกำลังผลิตไม่เท่ากับความต้องการรวม
Sensitivity Analysis: วิเคราะห์ว่าการเปลี่ยนข้อมูลนำเข้าทำให้คำตอบเปลี่ยนอย่างไร
Decision Support: ใช้ผลคำนวณประกอบการตัดสินใจ โดยยังต้องพิจารณาปัจจัยที่ไม่มีในตัวแบบ

ตรวจสอบสมดุลของข้อมูลตั้งต้น

โรงงานเดิมผลิตรวม 27,000 + 20,000 = 47,000 หน่วย/สัปดาห์ โรงงานใหม่ที่เลือกมีกำลังผลิต 25,000 หน่วย/สัปดาห์ รวมเป็น 72,000 หน่วย/สัปดาห์ เท่ากับความต้องการทั้งหมด 72,000 หน่วย/สัปดาห์ จึงเป็น Balanced Transportation Problem และทุกโรงงานที่เลือกต้องใช้กำลังผลิตเต็ม 100% ภายใต้โจทย์ต้นฉบับ

ตัวอย่างการแปลค่าต้นทุน: โรงงาน ค. มีต้นทุนผลิต 70 บาท/หน่วย และส่งไปลูกค้า ถ. เสียค่าขนส่ง 8 บาท/หน่วย ดังนั้นต้นทุนรวมของเส้นทาง ค. → ถ. เท่ากับ 78 บาท/หน่วย หากส่ง 16,000 หน่วย จะเกิดต้นทุน 1,248,000 บาท สำหรับสินค้าบนเส้นทางนี้
สมมติฐานและขอบเขตการวิเคราะห์ (Assumptions & Scope)
(1) สินค้าทุกหน่วยเป็นชนิดที่ใช้ทดแทนกันได้ และส่งจากโรงงานใดก็ได้ (2) มีหนึ่งช่วงเวลาการวิเคราะห์คือหนึ่งสัปดาห์ (3) ต้นทุนผลิตและขนส่งต่อหน่วยคงที่และไม่ติดลบ (4) ทุกเส้นทางในตารางอนุญาตให้ขนส่ง (5) ความต้องการแต่ละลูกค้าต้องได้รับครบ (6) กำลังผลิตแต่ละโรงงานเป็นเพดาน ไม่ใช่ข้อบังคับให้ผลิตเต็มเมื่อมีส่วนเกิน (7) ยังไม่ได้รวมค่าที่ดิน ค่าเปิดโรงงาน เงินลงทุนเริ่มต้น ภาษี ค่าใช้จ่ายคงที่ ระยะเวลา และความเสี่ยง

ข้อแตกต่างที่สำคัญ: ตัวแบบนี้เป็นการเปรียบเทียบตัวเลือกทำเลแบบกำหนดไว้ล่วงหน้า (Scenario-Based Facility Location) ไม่ใช่แบบจำลองกำหนดตำแหน่งพิกัดทางภูมิศาสตร์โดยตรง และไม่ใช่แบบจำลองต้นทุนตลอดอายุโครงการ

METHODOLOGY

ตัวแก้ปัญหาหลัก: Minimum-Cost Flow ด้วยอัลกอริทึม Successive Shortest Augmenting Path (ใช้ node potentials และ reduced cost) ทำงานภายในเบราว์เซอร์โดยไม่ต้องใช้ Excel Solver หรือเชื่อมต่ออินเทอร์เน็ต โดยคำนวณต้นทุนรวมต่อหน่วย Pi+Cij ของทุกเส้นทางพร้อมกัน

อัลกอริทึมหลักที่ใช้ในโปรแกรมนี้: Minimum-Cost Flow แบบ Successive Shortest Path

โปรแกรมไม่ได้หยุดเพียงการสร้างคำตอบเริ่มต้น แต่แก้ปัญหาเชิงเหมาะที่สุดบนโครงข่ายโดยตรง ผ่านแนวคิดของ Minimum-Cost Flow ร่วมกับ reduced-cost potentials เพื่อหาว่าควรส่งสินค้าเท่าใดในแต่ละเส้นทาง จึงจะทำให้ ต้นทุนการผลิต + ต้นทุนการขนส่ง ต่ำที่สุด ภายใต้ข้อจำกัดด้านกำลังการผลิตและความต้องการของลูกค้า

ขยายความแนวคิดอัลกอริทึม

ในเชิงคณิตศาสตร์ ปัญหานี้สามารถแปลงเป็นปัญหาการไหลในโครงข่าย (network flow) ได้ โดยสร้างโหนดต้นทางแทนโรงงาน โหนดปลายทางแทนลูกค้า และเส้นเชื่อมระหว่างโรงงานกับลูกค้าแทน “ทางเลือกในการส่งสินค้า” แต่ละเส้นมี capacity และ cost กำกับอยู่

  1. สร้างโครงข่าย: มีเส้นจาก Source → โรงงาน, โรงงาน → ลูกค้า, และ ลูกค้า → Sink
  2. กำหนดต้นทุนต่อหน่วย: สำหรับเส้นโรงงาน → ลูกค้า ใช้ค่า Pi + Cij
  3. ส่งการไหลทีละรอบ: หาเส้นทางที่มีต้นทุนส่วนเพิ่มต่ำที่สุดจาก Source ไป Sink แล้วส่งปริมาณได้มากที่สุดเท่าที่ข้อจำกัดอนุญาต
  4. อัปเดต residual network: หลังส่งสินค้าแต่ละรอบ โปรแกรมจะปรับความจุคงเหลือและสร้างเส้นย้อนกลับเพื่อใช้ตรวจสอบว่ามีทางปรับลดต้นทุนได้อีกหรือไม่
  5. หยุดเมื่อครบความต้องการ: เมื่อความต้องการของลูกค้าทั้งหมดถูกเติมเต็ม จึงได้คำตอบที่เป็นไปได้ และตรวจสอบ optimality ต่อด้วย residual network

เพื่อให้การหาเส้นทางสั้นที่สุดทำได้มีเสถียรภาพ โปรแกรมใช้ potential ช่วยปรับ reduced cost ทำให้ต้นทุนเชิงคำนวณไม่ติดลบระหว่างรอบ ซึ่งเป็นเทคนิคมาตรฐานของวิธี Successive Shortest Path

เป็นวิธีสร้างคำตอบเริ่มต้นอย่างง่าย โดยเริ่มจัดสรรจากมุมซ้ายบนของตารางแล้วเลื่อนไปตามแถวและคอลัมน์ จุดเด่นคือเข้าใจง่าย แต่ไม่ได้คำนึงถึงต้นทุน จึงมักไม่ใช่คำตอบที่ดีที่สุด

Algorithm B

Least Cost Method

เป็นวิธีสร้างคำตอบเริ่มต้นที่มองต้นทุนมากขึ้น โดยเลือกจัดสรรในช่องที่มีต้นทุนต่ำก่อน เหมาะสำหรับใช้เปรียบเทียบเพื่อการเรียนรู้ แต่ยังไม่รับประกัน optimality

Algorithm C

Successive Shortest Path Min-Cost Flow

เป็นอัลกอริทึมหลักของโปรแกรมนี้ ใช้หาคำตอบที่เหมาะสมที่สุดในระดับโครงข่าย จึงตอบโจทย์งานตัดสินใจเชิงวิศวกรรมได้แม่นยำกว่า heuristic เริ่มต้น

Why this one?

เหตุผลที่เลือกใช้

เพราะโจทย์มีขนาดไม่ใหญ่มาก แต่ต้องการความถูกต้องระดับวิชาการ อัลกอริทึมนี้จึงให้ทั้งความเร็ว ความโปร่งใสในการอธิบาย และความสามารถในการตรวจสอบ optimality ได้ในตัว

ลำดับการคำนวณในโปรแกรม

Step 1 · อ่านข้อมูล

รับค่าต้นทุนขนส่ง ต้นทุนผลิต กำลังผลิต และความต้องการ จากตารางที่ผู้ใช้แก้ไขได้

Step 2 · แยก 3 สถานการณ์

คำนวณแยกสำหรับชุดโรงงาน ก.+ข.+ค., ก.+ข.+ง. และ ก.+ข.+จ. เพื่อเปรียบเทียบทำเลใหม่ทีละทางเลือก

Step 3 · หาค่าเหมาะสมที่สุด

ใช้ Min-Cost Flow เพื่อหาปริมาณส่งในแต่ละเส้นทางให้ต้นทุนรวมต่ำที่สุด ภายใต้ข้อจำกัดทั้งหมด

Step 4 · ตรวจสอบและสรุปผล

ตรวจสอบ feasibility, optimality และจัดอันดับทำเล พร้อมสรุปบทวิเคราะห์และผลประหยัดเชิงเปรียบเทียบ

ตัวอย่างช่วยทำความเข้าใจ: ทำไมไม่เลือกเฉพาะเส้นทางที่ถูกที่สุด?

สำหรับการส่งสินค้าไปยังลูกค้า ถ. เมื่อนำต้นทุนผลิตรวมกับค่าขนส่ง จะพบว่า โรงงาน ค. → ถ. มีต้นทุน 70 + 8 = 78 บาท/หน่วย ขณะที่โรงงาน ก. → ถ. เท่ากับ 73 + 11 = 84 บาท/หน่วย และโรงงาน ข. → ถ. เท่ากับ 72 + 11 = 83 บาท/หน่วย

แม้เส้นทาง ค. → ถ. จะมีต้นทุนต่อหน่วยต่ำกว่า แต่โรงงาน ค. มีกำลังผลิตจำกัดเพียง 25,000 หน่วย/สัปดาห์ และอาจจำเป็นต้องส่งให้ลูกค้ารายอื่นด้วย อัลกอริทึมจึงต้องจัดสรรเส้นทางทั้งระบบพร้อมกัน โดยสามารถย้อนปรับการส่งเดิมผ่าน residual edges เพื่อค้นหาต้นทุนรวมที่ต่ำที่สุด ไม่ใช่ตัดสินใจจากช่องที่มีตัวเลขต่ำที่สุดเพียงช่องเดียว

หลักฐานความเหมาะสมที่สุด: หลังจัดสรรครบทุกลูกค้า โปรแกรมตรวจสอบว่าไม่เหลือวงจรต้นทุนติดลบในโครงข่ายส่วนเหลือ เมื่อเงื่อนไขความเป็นไปได้ครบถ้วนและไม่พบวงจรดังกล่าว คำตอบที่ได้จึงเป็นต้นทุนต่ำที่สุดภายใต้แบบจำลองปัจจุบัน

โปรดคำนวณก่อนเพื่อเปรียบเทียบวิธี
ขั้นที่ 1

Feasibility

ผลรวมแต่ละแถวไม่เกินกำลังผลิต ผลรวมแต่ละคอลัมน์เท่าความต้องการ และปริมาณไม่มีค่าติดลบ

ขั้นที่ 2

Optimality

ตรวจสอบว่าไม่มีวงจรต้นทุนติดลบที่ปรับปรุงคำตอบได้อีกใน residual network ของระบบ

ขั้นที่ 3

Engineering Review

ตรวจสอบความสมเหตุสมผลทางปฏิบัติและผลกระทบของข้อมูลใหม่ก่อนใช้งานตัดสินใจจริง

ข้อแตกต่างของ Northwest Corner, Least Cost และ Optimal Solution
Northwest Corner Rule: จัดสรรปริมาณเริ่มจากมุมซ้ายบนของตาราง ไม่พิจารณาต้นทุน จึงอาจได้ค่าใช้จ่ายสูง
Least Cost Method: จัดสรรจากช่องที่มีต้นทุนต่อหน่วยต่ำที่สุดก่อน เป็นวิธีฮิวริสติกสำหรับหาคำตอบเริ่มต้น แต่ไม่รับประกันค่าเหมาะสมที่สุด
Optimal (Min-Cost Flow): ปรับจัดสรรทั้งระบบเพื่อให้ต้นทุนต่ำที่สุด โดยตรวจสอบเงื่อนไขการไหลของโครงข่ายเพิ่มเติม

การเปรียบเทียบ Northwest Corner และ Least Cost ในโปรแกรมเปิดแสดงเฉพาะกรณี Supply = Demand เพราะทั้งสองวิธีในส่วนนี้ออกแบบสำหรับตารางขนส่งสมดุล ส่วนตัวแก้ปัญหาหลักรองรับ Supply ≥ Demand ด้วย
